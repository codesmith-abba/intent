# Parser

The Parser is the second stage of the ITL compiler.

Its responsibility is to read the token stream produced by the lexer and construct an Abstract Syntax Tree (AST).

The parser verifies that the program follows the grammatical rules of the language.

It does not determine whether the program is semantically correct.

---

# Purpose

The parser converts a sequence of tokens into a structured representation of the application.

Its responsibilities include:

- parsing declarations
- constructing the AST
- enforcing grammar rules
- reporting syntax errors
- preserving declaration hierarchy

---

# Position in the Compiler

```
ITL Source
      │
      ▼
Lexer
      │
      ▼
Token Stream
      │
      ▼
Parser
      │
      ▼
Abstract Syntax Tree (AST)
```

---

# Input

The parser receives the token stream generated by the lexer.

Example:

```
APP
STRING("Portfolio")
LEFT_BRACE

PAGE
STRING("home")
LEFT_BRACE

THEME
STRING("dark")

RIGHT_BRACE

RIGHT_BRACE

EOF
```

---

# Output

The parser produces an Abstract Syntax Tree (AST).

Example:

```
App
└── Page
    └── Theme
```

The AST preserves the logical structure of the application.

---

# Abstract Syntax Tree

The AST represents the hierarchical structure of an ITL application.

Example:

```itl
app $Portfolio {

    page $home {

        hero $main {

        }

    }

}
```

Produces:

```
App
└── Page
    └── Hero
```

Each declaration becomes a node within the tree.

---

# Parsing

The parser processes tokens from beginning to end.

When it encounters a declaration, it constructs the corresponding AST node and recursively parses any child declarations.

For example:

```itl
page $home {

    hero $main {

    }

}
```

The parser recognizes:

- a `page` declaration
- the page name
- the page block
- the nested `hero` declaration

---

# Grammar Validation

The parser ensures that declarations follow the language grammar.

Example:

Valid:

```itl
page $home {

}
```

Invalid:

```itl
page {

}
```

Compiler error:

```
Expected page name.
```

---

# Nested Declarations

Declarations that define scopes may contain child declarations.

Example:

```itl
page $home {

    hero $main {

    }

}
```

The parser recursively parses nested blocks until the matching closing brace is found.

---

# Error Reporting

When invalid syntax is encountered, the parser reports a syntax error.

Example:

```itl
page $home
```

Compiler error:

```
Expected '{'.
```

Another example:

```itl
app $Portfolio {

    page $home {

}
```

Compiler error:

```
Expected '}'.
```

The parser stops parsing when it encounters unrecoverable syntax errors.

---

# Compiler Behavior

The parser processes tokens in order.

For each declaration it:

1. recognizes the declaration
2. validates its grammar
3. creates the corresponding AST node
4. parses child declarations
5. attaches the node to the tree

When parsing completes successfully, the root AST node is returned.

---

# Relationship with the Analyzer

The parser only validates grammar.

For example:

```itl
page $home {

    hero $main {}

}
```

This is grammatically valid.

Whether the declaration is semantically valid is determined later by the Semantic Analyzer.

---

# Notes

- The parser consumes tokens produced by the lexer.
- The parser constructs the Abstract Syntax Tree (AST).
- The parser validates grammar only.
- The parser does not perform semantic validation.
- Syntax errors are reported during parsing.
